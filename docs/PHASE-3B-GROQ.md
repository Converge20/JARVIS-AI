# Phase 3B — Groq text intelligence

AXIOM now uses GroqCloud through its official OpenAI-compatible endpoint, using the already installed OpenAI JavaScript SDK. This SDK name does not imply OpenAI API usage: the backend pins `https://api.groq.com/openai/v1`, reads only `GROQ_API_KEY`, and has no fallback to OpenAI or another provider. No dependency was added or upgraded in this phase.

The default is **`openai/gpt-oss-20b`**, a currently supported, tool-capable text model hosted by Groq. The `openai/` prefix identifies its open-weight model family, not an OpenAI API call. Configure a different Groq Responses/function-calling-capable model with server-side `GROQ_MODEL`. GPT OSS uses low reasoning effort to conserve the output allowance. No built-in web search, remote tools, code execution, or speech tools are enabled.

Use an organisation/project on Groq's **Free Plan**. Model access and exact free quotas depend on the current account; check the Free Plan tab and your account limits. The application cannot determine whether your key belongs to a free or paid organisation. It never changes billing, upgrades plans, requests a paid service tier, or silently switches providers/models. Local limits are usage safeguards, not a guarantee of free billing on an already-paid account. Keep the account on the Free Plan; no upgrade is necessary for this implementation.

Official references, checked 1 November 2026:

- [Groq OpenAI compatibility](https://console.groq.com/docs/openai)
- [GPT OSS 20B model](https://console.groq.com/docs/model/openai/gpt-oss-20b)
- [Groq Responses API and unsupported fields](https://console.groq.com/docs/responses-api)
- [Rate limits and account-specific quotas](https://console.groq.com/docs/rate-limits)

Groq documents Responses as beta. Its unsupported `store` field is deliberately omitted; no `previous_response_id` or server-side conversation storage is used. Recent messages are sent explicitly on each turn. Groq's data policies apply: this implementation does not claim zero provider retention.

## Restart your existing Codespace and load the secret

Your existing repository-scoped **Codespaces secret named `GROQ_API_KEY`** supplies the server credential. Do not paste it into this chat, a command, a frontend input, a `VITE_*` variable, or Git.

1. If the Codespace was running before you saved the secret, open [GitHub Codespaces](https://github.com/codespaces), use its **… → Stop codespace**, then open that same Codespace again. Do not delete it or create a new one. A restart lets newly configured secrets enter its environment. A simple browser page reload may not refresh the terminal environment.
2. In the Codespaces browser editor, use **Terminal → New Terminal**. Stop an old running preview with **Control+C** in its terminal first. Then run:

   ```bash
   git switch feat/axiom-neural-interface
   git pull --ff-only origin feat/axiom-neural-interface
   npm ci
   ```

   If Git reports local changes or divergence, preserve them and resolve that message before proceeding; do not force reset your workspace.

3. Launch the existing application, using the inherited secret without printing it:

   ```bash
   export GROQ_ENABLED=true
   export AXIOM_ALLOWED_ORIGIN="https://${CODESPACE_NAME}-5173.app.github.dev"
   __VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS="${CODESPACE_NAME}-5173.app.github.dev" \
     npm run dev -- --port 5173 --strictPort
   ```

   The default model needs no extra setting. To change it for this launch, set `GROQ_MODEL` in the server environment. You can instead add non-secret `GROQ_ENABLED=true` and `GROQ_MODEL=openai/gpt-oss-20b` to an existing ignored `.env` using the editor, then restart the server. Do not overwrite your existing `.env` or copy credentials into it unnecessarily. Inherited environment values take precedence over `.env`.

4. In **Ports**, open **5173**, keep **Port Visibility: Private**, and choose **Open in Browser**. Do not forward backend port 3001 separately. Use the actual URL generated by Codespaces. If your organisation supplies a different preview domain, substitute its exact origin/hostname in the two variables above, without a trailing slash on the origin. Do not broadly allow all hosts.
5. In Conversation, select **Check connection**. **Configured · not verified** means the key and enable flag are present; this check makes no provider request. Your first successful question changes the status to **Groq connected**. It is not a fabricated success indicator.

Everything runs in the cloud browser workspace. Nothing needs installing on your Mac. Codespaces usage is separate from Groq's Free Plan and subject to your GitHub quota.

## First real conversation and task test

After checking that the key belongs to your free-tier organisation:

1. Send **“Explain compound interest in simple terms.”** The brain displays Analyzing while the actual request is pending. A successful text reply returns it to Idle; no fake speech waveform starts.
2. Follow up with **“Give me an example using £1,000 at 5% for two years.”** AXIOM sends the recent conversation context to Groq. These are model-generated answers, not a scripted demo.
3. Ask **“Create a task to study finance tomorrow.”** Review the proposed title/date, then select **Confirm task change**. Nothing is saved before confirmation. Refresh to verify the local task persists.
4. Ask **“Show my outstanding assignments.”** A real `list_tasks` operation retrieves the browser's supplied task snapshot; the brain briefly acknowledges the completed retrieval. This is local task retrieval, not internet research.
5. Ask to complete a named task, or delete it. Existing task changes require confirmation; **Cancel task change** preserves it. Ambiguous matches should prompt clarification. Stale proposals are rejected against the current task snapshot.

Because free-tier allowances are modest, the conservative local allowance may permit only one tool turn or two short text turns per minute. Wait about a minute between batches of tests. A task-tool turn can require two provider calls. If a rate-limit message appears, wait the displayed interval; do not repeatedly click Send. There are no automatic retries. If a daily provider quota is exhausted, consult Groq’s account limits and wait for its reset; the short application cooldown does not reset a provider quota.

## Configuration and limits

`.env.example` contains placeholders only. Old `OPENAI_API_KEY`, `OPENAI_MODEL`, and `OPENAI_ENABLED` settings no longer enable or authenticate requests. Voice and microphone remain disabled regardless of those settings.

| Server variable                  | Default              | Purpose                                                                                                     |
| -------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `GROQ_API_KEY`                   | unset                | Existing Codespaces secret; server only                                                                     |
| `GROQ_ENABLED`                   | `false`              | Explicitly enable your free-tier connection                                                                 |
| `GROQ_MODEL`                     | `openai/gpt-oss-20b` | Supported Groq text/function-calling model                                                                  |
| `AXIOM_MAX_REQUESTS_PER_MINUTE`  | 3                    | User messages per minute; maximum configurable value 10                                                     |
| `AXIOM_MAX_API_CALLS_PER_MINUTE` | 6                    | Counts both tool turns; maximum 30                                                                          |
| `AXIOM_MAX_API_CALLS`            | 100                  | Hard SDK-attempt budget per server process; maximum 1000                                                    |
| `AXIOM_MAX_OUTPUT_TOKENS`        | 1024                 | Per-call output cap including model reasoning; maximum 2048                                                 |
| `AXIOM_MAX_INPUT_BYTES`          | 12000                | UTF-8 JSON limit including instructions, task context, tool definitions and follow-up output; maximum 24000 |
| `AXIOM_MAX_TOKENS_PER_MINUTE`    | 6000                 | Approximate input reservation plus capped output across all calls; maximum 32000                            |
| `API_PORT`                       | 3001                 | Loopback backend; Vite proxies `/api`                                                                       |
| `AXIOM_ALLOWED_ORIGIN`           | local HTTP Host      | Exact trusted origin for HTTPS private previews                                                             |

The token reservation is `ceil(request UTF-8 bytes / 3) + 128 + output cap`. This is a conservative heuristic for typical English, **not an exact tokenizer or guaranteed quota calculation**. Groq enforces actual organisation-wide limits shared with other apps. Failed upstream attempts consume the local allowance too. Limits reset in memory: minute allowances reset after a minute; restarting the process resets the process budget. They are not a persistent billing ledger or a security boundary for public multi-user hosting.

At most one AI request is in flight, with at most one task tool and two provider calls per message. Browser double-submit prevention, duplicate request IDs, input validation, exact origin checks, JSON/body limits, a 20-second SDK timeout and 45-second whole-turn deadline remain in place. SDK retries and SDK logging are explicitly disabled. Errors never return raw Groq response text, headers containing credentials, or request data.

Missing credentials/disabled mode produce clear messages without an AI call. A Groq 429 returns a redacted message and bounded `Retry-After` cooldown (1–300 seconds, 60 if unspecified); further requests during that interval are refused locally. Model/authentication/network failures give actionable messages without a fake answer or paid fallback. On failed or incomplete tool turns, no task change is applied. Any generated task mutation still needs browser confirmation.

The browser sends up to 20 recent non-workspace chat messages, the local date and at most 200 tasks through same-origin `/api/chat`; the per-call byte cap can impose a lower practical context limit. Requests exceeding it fail before contacting Groq. Use **New conversation** to reduce history. Task context and chat leave the browser when enabled questions are submitted; tasks themselves remain locally stored. No conversations, keys or task contents are logged or retained by this Node process. Chat remains session-only.

## Validation and current limits

```bash
npm audit
npm audit --omit=dev
npm test
npm run build
npm run test:e2e
```

Tests inject fake credentials and provider responses. The real SDK construction is exercised with an intercepted fetch asserting that requests go only to `https://api.groq.com/openai/v1/responses`, use the Groq model, omit unsupported fields, and do not return credentials. Rate limits/cooldown, input and token allowances, failure redaction, model configuration, task tools and history are covered. Browser tests explicitly clear `GROQ_API_KEY`, set `GROQ_ENABLED=false`, use a dedicated backend port and refuse to reuse an existing potentially enabled preview.

The current Codex environment has no Groq secret and its network policy does not permit `api.groq.com`. No real Groq or OpenAI inference request was made during development or automated testing. Your separate Codespaces secret is not accessible here. First live authentication, free-tier model access and answer quality must be verified in your own restarted Codespace.

The existing anatomical meshes, licensed model attribution, six manual state previews, task storage, navigation, responsive layout, rendering fallbacks and voice-disabled policy remain intact. Animations illustrate application events, not measurements of AI cognition. General-knowledge answers do not use web retrieval. The previously reported GitHub orange-pixel timeout remains a separate CI rendering/test issue and is reported if it recurs; visual assertions are not weakened to claim success.

For a full production build preview in a private development workspace, `npm run build` then `npm start` serves `dist/` plus `/api` from loopback port 3001. This is not a public deployment. No service upgrades, billing changes, microphone access, paid calls or merges are part of Phase 3B.
